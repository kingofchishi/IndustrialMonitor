# 面试讲解与简历写法 · Industrial Monitor

> 配合项目文档使用。目标：让你在 30 秒内说清项目，在 2 分钟内讲出技术深度，并能接住追问。

---

## 1. 一句话定位

> 一个 .NET 8 + WinForms 的工业设备监控上位机，支持多设备异步采集、实时趋势、越限报警、历史查询、SQLite 持久化与 CSV 导出。

---

## 2. 30 秒版本

> 这个项目是我为上位机岗位做的设备监控系统。后台 `MonitoringService` 按 250ms 调度、按设备自己的周期采集模拟设备数据，批量写入 SQLite；前台 WinForms 实时显示趋势、报警和历史。项目按 Core/Infrastructure/UI 分层，使用 Repository、Strategy、Observer 和 DI；重点解决了 UI 不阻塞、采集不重入、报警不重复、历史分页和 CSV 导出。

---

## 3. 2 分钟版本

### 3.1 业务

工厂现场需要实时监控温度、压力、转速、液位；超过上下限要报警；历史数据要能追溯；操作员要能确认报警。

### 3.2 架构

```text
WinForms UI
  ↓ 调用 / 订阅事件
MonitoringService（采集编排、报警状态、事件）
  ↓ 依赖接口
Core：Models + IRepository + IDeviceClient + 报警规则
  ↑ 实现
Infrastructure：SQLite 仓储 / 模拟设备 / CSV
```

- UI 不写 SQL；
- Core 不引用 WinForms/SQLite；
- `Program.cs` 是唯一组合根；
- `IDeviceClient` 可替换成 Modbus/串口；
- `IDeviceRepository` 等可替换成 MySQL。

### 3.3 采集

- `MonitoringService` 单例；
- 每 250ms 检查一次；
- 每台设备有独立 `SamplingIntervalMs`；
- 只在到期时读取；
- `Task.Delay` + `CancellationToken`，不阻塞 UI；
- `SemaphoreSlim(1,1)` 防止采集重入；
- 批量写 Telemetry（事务）。

### 3.4 报警

- `AlarmEvaluator` 是纯函数：`>= HighLimit` 严重，`<= LowLimit` 警告；
- `_lastAlarmLevel` 保存上次等级；
- 只在状态迁移时插入新报警，避免高频刷屏；
- 报警确认记录操作员和时间。

### 3.5 UI

- 页面：运行总览、设备管理、历史数据、报警中心、系统设置；
- 自绘 `TrendChart`（GDI+）和 `KpiCard`；
- 后台事件通过 `MainForm.RunOnUi` → `BeginInvoke` 回 UI 线程；
- `DataGridView` 绑定模型，`CellFormatting` 做状态着色。

### 3.6 数据

- SQLite，WAL；
- 参数化 SQL；
- `LIMIT/OFFSET` 分页；
- 索引 `(DeviceId, CollectedAtUtc)`、`(IsAcknowledged, OccurredAtUtc)`；
- 测试用临时 SQLite 库。

### 3.7 不足

没有真实 Modbus/串口驱动、没有登录权限、没有生产级日志/告警通知、没有大规模压测。这些是下一步。

### 版本 A（偏业务）

**工业设备监控与数据采集系统**｜.NET 8 / WinForms / SQLite

```text
                   │ events / service calls

│ scheduler / cancellation / alarm     │
└──────────────────┬───────────────────┘
                   │ interfaces
┌──────────────────▼───────────────────┐
│ Core: Models + Abstractions + Rules  │
└──────────────────▲───────────────────┘
                   │ implements
┌──────────────────┴───────────────────┐
│ Infrastructure: SQLite / Simulator   │
└──────────────────────────────────────┘
```

然后补一句：

> 依赖方向是 UI → Core ← Infrastructure，Infrastructure 通过实现 Core 的接口来提供细节。

## 6. 高频追问

### Q1：为什么用 SQLite？

单机上位机，零配置、单文件、易备份；不需要安装数据库服务。MySQL 适合多客户端/集中部署。本机 MySQL 有服务但无凭据，所以没有硬编码密码。

### Q2：为什么不用 EF Core？

SQL 简单，ADO.NET 更透明，能直接讲索引、参数化、事务；Repository 已隔离，后续可换 EF Core。

### Q3：报警怎么去重？

`_lastAlarmLevel` 保存每台设备上次等级；等级变化才插新报警；持续越限不重复；回到 Normal 清空状态。

### Q4：UI 怎么更新？

后台事件 → `MainForm.RunOnUi` → `InvokeRequired` → `BeginInvoke` → 页面更新控件。

### Q5：为什么用 `BeginInvoke` 不用 `Invoke`？

`Invoke` 会同步等 UI 线程，后台采集可能被 UI 卡住；`BeginInvoke` 异步投递后立即返回。

### Q6：采集会不会重入？

`SemaphoreSlim(1,1)` + `finally Release`，同一时刻只有一个采集流程。

### Q7：关闭程序时后台还在跑怎么办？

`FormClosing` 先 `await _monitor.StopAsync()`，取消 token 并等待循环结束，再真正 Close。

### Q8：SQLite 并发写会锁吗？

WAL + `busy_timeout=5000`，连接每次独立创建；批量写在事务里；UI 查询和采集写入尽量错开。生产可加重试/队列。

### Q9：为什么 `Task.Delay` 不 `Thread.Sleep`？

不阻塞线程、可取消、停止采集响应快。

### Q10：怎么接 Modbus？

实现 `IDeviceClient.ReadAsync`，替换 DI 注册；补连接、超时、重连、寄存器映射；Core/UI 不变。

### Q11：数据量大了怎么办？

索引、分页、批量写、保留策略、历史归档/分区、曲线降采样；再评估 MySQL/时序库。

### Q12：为什么 UI 用代码构建而不是 Designer？

动态卡片/图表多，代码更易审查和复现；控件本身仍是标准 WinForms，文档给了控件/属性表，可以按设计器复刻。

### Q13：最大的难点？

不是“写界面”，而是“后台采集 + UI 线程 + 报警状态 + SQLite 并发”同时正确；尤其是停止/关闭时的生命周期。

### Q14：最大的不足？

没有真实设备协议、权限、生产日志/告警通知、压力测试。下一步补这些。

### Q15：如果重做一次？

- 抽 `IDeviceClient` 的连接状态/重连策略；
- 加日志与指标；
- 增加报警迟滞；
- 把 UI 页面拆成更明确的 Presenter；
- 用集成测试覆盖 `MonitoringService`。
